# Печной двор — Заказы

Готовый Telegram-бот и Mini App для общего учёта заказов. Владелец, сборщик и курьер открывают одного бота и видят одну базу заказов.

## Что умеет

- принимает **пересланный текстовый заказ** и сохраняет его с номером `№1`, `№2` и так далее;
- хранит исходный полный текст, комментарий, автора и историю последнего изменения;
- открывает Mini App по кнопке **«Открыть заказы»** в Telegram;
- показывает все заказы карточками: один столбец на телефоне, два — на iPad;
- меняет статус одним выбором из списка; комментарий сохраняется отдельной кнопкой;
- каждые 4 секунды обновляет список: изменения коллег появляются почти сразу;
- проверяет подпись Telegram Mini App на сервере — доступ нельзя получить, просто открыв URL в браузере;
- работает с SQLite на компьютере и PostgreSQL для общей онлайн-базы.

Статусы: `Новый`, `На сборку`, `Собирается`, `Не хватает позиции`, `Собран`, `Передан в доставку`, `Отправлен СДЭК`, `Передан курьеру`, `Доставлен`.

## Состав проекта

```text
app/
  bot.py          Telegram-бот и приём пересланных заказов
```

## Быстрый локальный запуск

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и заполните:

```dotenv
BOT_TOKEN=токен_от_BotFather
WEBAPP_URL=https://ваш-публичный-https-адрес
DATABASE_URL=sqlite:///./orders.db
```

Затем запустите:

```bash
python main.py
```

Проверка сервера: откройте [http://localhost:8000/health](http://localhost:8000/health). Локальная база появится как файл `orders.db` и не требует настройки.

### Тест интерфейса без Telegram

В `.env` временно установите `DEV_MODE=true`, перезапустите сервер и откройте [http://localhost:8000/?dev=1](http://localhost:8000/?dev=1). Этот режим **нельзя** оставлять включённым на опубликованном сайте.

Telegram открывает Mini App только по публичному HTTPS-адресу. Для теста бота на своём компьютере сначала дайте локальному серверу временный HTTPS-адрес (например, Cloudflare Tunnel или ngrok), запишите этот адрес в `WEBAPP_URL`, затем перезапустите приложение.

## Создание бота в BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Укажите отображаемое имя, например `Печной двор — Заказы`, и уникальный username, который заканчивается на `bot`.
3. Скопируйте полученный токен в `BOT_TOKEN` файла `.env`. Токен — пароль бота: не отправляйте его в чат и не добавляйте в Git.
4. Запустите приложение хотя бы один раз с заполненными `BOT_TOKEN` и `WEBAPP_URL`. Оно само установит кнопку меню **«Открыть заказы»**.
5. Дополнительно можно настроить главный экран в BotFather: `/mybots` → ваш бот → **Bot Settings** → **Configure Mini App** → **Enable Mini App**. Укажите тот же `WEBAPP_URL`. Тогда у бота появится заметная кнопка запуска в профиле.
6. Откройте бота, отправьте `/start`, затем перешлите ему обычное текстовое сообщение с заказом. В ответ придёт номер нового заказа.

## Ограничение доступа сотрудникам

По умолчанию работать может каждый, кому вы дали ссылку на бота. Для рабочего бота лучше ограничить список.

1. Каждый сотрудник открывает бота и отправляет `/myid`.
2. В `.env` внесите полученные числа через запятую:

```dotenv
ALLOWED_TELEGRAM_IDS=123456789,987654321,555555555
```

3. Перезапустите приложение.

Теперь посторонний пользователь не сможет ни добавлять заказы, ни открывать их в Mini App. Команда `/myid` остаётся доступной, чтобы можно было добавить нового сотрудника.

## Онлайн-вариант: Railway + PostgreSQL

Это самый простой вариант для общей базы: один постоянно работающий сервис запускает сайт и бота, а PostgreSQL хранит данные отдельно от приложения.

1. Создайте пустой репозиторий на GitHub и загрузите в него **весь этот проект**, кроме `.env`.
2. В [Railway](https://railway.app) создайте проект и выберите деплой из GitHub-репозитория. Файлы `Dockerfile` и `railway.json` уже подготовлены.
3. В этом же проекте добавьте сервис **PostgreSQL**. В настройках переменных приложения создайте `DATABASE_URL`, выбрав ссылку на переменную подключения созданной базы (не вставляйте её в код).
4. В настройках приложения добавьте переменные:

```dotenv
BOT_TOKEN=реальный_токен_BotFather
DATABASE_URL=ссылка_на_DATABASE_URL_сервиса_PostgreSQL
ALLOWED_TELEGRAM_IDS=ID_владельца,ID_сборщика,ID_курьера
DEV_MODE=false
```

5. После первого деплоя Railway выдаст публичный домен. Добавьте туда `WEBAPP_URL=https://ваш-домен` и перезапустите/передеплойте сервис.
6. Зайдите в бота и отправьте `/start`: приложение обновит его кнопку меню. При желании тот же URL укажите в **Configure Mini App** у BotFather.
7. Проверьте `https://ваш-домен/health`, перешлите тестовый заказ и откройте Mini App с двух разных аккаунтов.

В настройках Railway оставьте **один экземпляр приложения**: бот использует long polling, поэтому одновременно должен работать только один его процесс. Данные останутся в PostgreSQL даже при новом деплое приложения.

### Альтернатива: Supabase PostgreSQL

Если нужна отдельная управляемая база, создайте проект в [Supabase](https://supabase.com), нажмите **Connect** и возьмите строку подключения. Для постоянно работающего Railway-сервиса удобно выбрать **Session pooler**. Укажите её в `DATABASE_URL`, например:

```dotenv
DATABASE_URL=postgresql://postgres.проект:пароль@aws-регион.pooler.supabase.com:5432/postgres?sslmode=require
```

Приложение автоматически распознаёт обычные `postgres://` и `postgresql://` строки и подключается к PostgreSQL через безопасный драйвер. SQLite в облаке для общей базы не используйте: файл может быть потерян при новом развёртывании.

Официальные справки: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [подключение Supabase PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres).

## Ежедневная работа

1. Владелец пересылает заказ боту.
2. Бот сразу присваивает ему номер и статус **«Новый»**.
3. Сборщик открывает «Открыть заказы», выбирает статус, пишет комментарий при необходимости.
4. Курьер видит тот же список и ставит «Передан курьеру» или «Доставлен».

## Проверка проекта

После установки зависимостей можно выполнить проверку подписи Telegram Mini App:

```bash
python -m unittest discover -s tests -v
```

Тесты не используют настоящий токен и не подключаются к Telegram.

## Важные примечания

- Бот сохраняет только текст пересланного сообщения или его подпись. Если заказ — только фотография/голосовое без текста, бот попросит переслать текст.
- У приложения нет удаления заказов намеренно: это снижает риск случайно потерять заказ. При необходимости заказ можно пометить статусом «Доставлен».
- `BOT_TOKEN`, `.env` и строку подключения к базе нельзя публиковать или пересылать посторонним.
